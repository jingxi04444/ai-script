# 画布与通告图真实接口接入说明

## 已接入

| 能力 | 入口 | 执行与存储 |
| --- | --- | --- |
| 模型下拉 | `GET /api/workflow/models` | 读取当前租户可用的 `sys_api_provider_config`；正式模式不展示内置演示模型 |
| 画布保存、校验、整图运行 | `/api/projects/{id}/workflow`、`/runs` | MySQL 工作流快照 → Redis Streams → Python runner → Spring Provider 网关；事件和节点耗时进入运行记录 |
| 文本、图片、视频、音乐、配音等单节点生成 | `/api/projects/{id}/workflow/runs` | 单节点及必要上游构成子图，使用同一真实执行链路；不再直接写入演示素材 |
| 导演台布局文字指令 | `/api/projects/{id}/workflow/runs` | 文本模型返回结构化坐标，浏览器校验对象 ID、锁定状态和坐标后应用；3D 预演仍在浏览器渲染 |
| 导演台截图 | 文件上传 API + 画布保存 API | 截图上传到文件存储并作为导演台参考节点进入画布 |
| 场景通告图 | `GET/PUT /api/projects/{id}/scene-notice`、`POST .../preview` | 服务端重新读取项目 Brief 和脚本，按场景上限分配“一个场景 × 一个产品”行，并版本化存入 `ai_scene_notice_plan` |
| 分镜“提示词”列 | 脚本生成与读取接口 | 新脚本要求模型写可执行指令；旧分镜表及模型漏列时补齐主体锁定、场景动作和运镜约束 |

## 尚未接通或依赖供应商能力

- 画布 Agent 的“根据描述搭建节点”仍是本地规则草案，不是 LLM 自动编排。
- 导演台上传的参考图目前仅在浏览器预览，尚未让视觉模型理解图片；文字布局调用是真实模型任务。
- 通告图的 AI 生图张数是计划数量，尚未为每一行自动创建批量图片生成任务；静态场景贴图是参考素材。
- 视频首尾帧、TTS 语速/采样率、音乐等高级参数需要按具体供应商的请求字段补专用映射。基础提示词与模型调用已走真实网关。
- 后台 Provider 必须分别配置并启用 `llm`、`image`/`vision`、`video`、`tts`、`music`、`editor`/`video_editor` 等类型；没有对应适配器时运行应失败，不回退为假结果。

## 部署前提

1. 已有环境先执行 `doc/global-database/mysql/migrations/20260904110000_workflow_runner.sql`（若此前未执行），再执行 `doc/global-database/mysql/migrations/20261006120000_scene_notice_plan.sql`。新库使用全局建库脚本即可。
2. Spring Boot 与 Python runner 指向相同 MySQL、Redis；两端配置同一个 `WORKFLOW_PROVIDER_GATEWAY_TOKEN`。在 runner 的 `.env` 中设置 `WORKFLOW_PROVIDER_GATEWAY_ENABLED=true`，正式运行保持 `WORKFLOW_DEMO_MODE_ENABLED=false`。
3. 启动 Spring Boot、Redis 与 Python runner；检查项目接口、runner `/health` 和模型后台配置。未配置真实网关时生成节点会明确失败，不会产生演示素材。

代码落地不等于已经实际调用供应商。联调时请用小样本、低成本模型先验证一条文本和一张图片，再扩大到视频批量生产。
