# 会员订阅模块开发设计

## 1. 设计目标

会员订阅模块负责套餐展示、购买、自动续费、升降级、取消续费、退款、权益判断、月度额度、积分账户和业务模块强制校验。

设计原则：

1. 套餐等级、销售价格和权益配置分离，避免全部写入一个 JSON。
2. 付费周期与权益重置周期分离，季付和年付仍按开通日逐月重置额度。
3. 支付订单保存商品快照，已售套餐不受后台后续改价影响。
4. 所有扣减、履约和回调支持幂等与并发安全。
5. 前端只控制展示，最终权限和额度由后端校验。
6. 免费用户同样拥有订阅和权益周期，免费脚本次数由后台配置。

## 2. 已确认业务规则

### 2.1 Brief 数量

- `BRIEF_MAX_ACTIVE` 表示用户当前可用的去重 Brief 总数，不按月重置。
- 一个 Brief 关联多个项目只计算一次。
- 通过分享加入项目的 Brief 也计算一次。
- 撤销项目关联后，如果该 Brief 已不属于用户任何项目，则不再计算。
- 超过降级后的上限时不删除已有数据，但禁止创建、复制、导入和加入新的共享 Brief。

### 2.2 免费脚本额度

- 免费用户拥有可配置的脚本生成次数。
- 使用 `SCRIPT_MONTHLY_LIMIT` 配置，按照免费订阅开通日逐月重置。
- 免费用户注册后自动创建免费订阅和首个月度权益周期。

### 2.3 升级和降级

- 升级支付成功后立即生效，按剩余价值抵扣并支付差价。
- 升级后的剩余额度为新套餐当期总额度减去当期已使用额度。
- 降级在当前付费周期结束后生效，生效前允许撤销。
- 取消自动续费后，当前权益保留到周期结束，之后切换为免费套餐。
- 退款成功后付费权益立即失效，已消耗额度和积分不回滚。

## 3. 领域拆分

```text
membership
├── plan                 套餐等级
├── sku                  月付、季付、年付等销售规格
├── benefit              权益定义与套餐权益值
├── subscription         用户订阅与状态变更
├── cycle                月度权益周期
├── entitlement          统一权限和额度服务
├── points               积分账户与流水
└── refund               退款与权益回收
```

## 4. 核心数据模型

### 4.1 `ai_membership_plan`

只表示会员等级，不保存具体价格和购买周期。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| plan_code | VARCHAR(40) | `free/light/pro/ultimate` |
| plan_name | VARCHAR(80) | 套餐名称 |
| plan_level | INT | 等级排序 |
| is_free | TINYINT | 是否免费 |
| description | VARCHAR(500) | 套餐说明 |
| display_order | INT | 展示顺序 |
| status | TINYINT | 上下架状态 |

### 4.2 `ai_membership_plan_sku`

表示月付、连续月付、季付、年付等具体商品。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| plan_id | BIGINT | 会员等级 |
| sku_code/sku_name | VARCHAR | SKU编码和名称 |
| billing_mode | VARCHAR(20) | `one_time/auto_renew` |
| period_unit | VARCHAR(20) | `month/quarter/year` |
| period_count | INT | 周期数量 |
| price/original_price | DECIMAL(14,2) | 售价和划线价 |
| refund_days | INT | 退款窗口 |
| status/display_order | INT | 状态和顺序 |

### 4.3 权益配置表

- `ai_membership_benefit_definition`：定义权益编码、类型、单位和重置方式。
- `ai_membership_plan_benefit`：保存每档套餐的权益值。
- 唯一索引：`(plan_id, benefit_id)`。

核心权益编码：

| 编码 | 重置方式 | 用途 |
|---|---|---|
| SCRIPT_MONTHLY_LIMIT | membership_month | 脚本月度生成次数 |
| BRIEF_MAX_ACTIVE | none | 当前有效 Brief 数量 |
| BRIEF_DETECT_POINT_COST | none | Brief 检测积分单价 |
| BRIEF_BATCH_IMPORT | none | Brief 批量导入 |
| BRIEF_COLLABORATION | none | Brief 共享协作 |
| TEMPLATE_ACCESS_SCOPE | none | 模板访问范围 |
| HOT_TEMPLATE_ACCESS | none | 热点模板 |
| CUSTOM_TEMPLATE_LIMIT | none | 自定义模板保存上限 |
| VIRAL_SIMPLE_POINT_COST | none | 简易解析积分单价 |
| VIRAL_SIMPLE_TRIAL_LIMIT | lifetime | 免费试用次数 |
| VIRAL_DEEP_POINT_COST | none | 深度解析积分单价 |
| POINTS_PER_10_YUAN | none | 积分购买比例 |
| DAILY_LOGIN_POINT | day | 每日登录奖励 |
| VIDEO_LAUNCH_BONUS_POINT | lifetime | 视频上线赠送积分 |
| REMOVE_WATERMARK | none | 去品牌水印 |
| TASK_CONCURRENCY_LIMIT | none | 并发任务数 |
| STORAGE_LIMIT_BYTES | none | 云端存储 |
| VIDEO_IMAGE_LIMIT | membership_month | 预告图片额度 |
| VIDEO_GENERATE_LIMIT | membership_month | 预告视频额度 |

`unlimited` 由统一权益服务解析，业务模块不得自行约定特殊数字。

### 4.4 `ai_user_subscription`

保存用户当前订阅、自动续费和待生效降级：

```text
tenant_id/user_id
plan_id/sku_id
status
auto_renew
start_time
current_period_start/current_period_end
benefit_anchor_time
next_renew_time
cancel_at_period_end/cancel_time
pending_plan_id/pending_sku_id/pending_effective_time
provider/agreement_no
plan_snapshot_json
version
```

订阅状态：

```text
active       正常生效
canceling    已取消续费，等待到期
past_due     自动续费失败，宽限期
expired      已到期
refunded     已退款
replaced     被新订阅替换
```

### 4.5 `ai_membership_benefit_cycle`

一条季付或年付订阅可以产生多个按月权益周期。核心字段：

```text
subscription_id/user_id/plan_id
cycle_no
cycle_start/cycle_end
status
benefit_snapshot_json
```

唯一索引：`(subscription_id, cycle_start)`。周期使用 `start.plusMonths(1)`，不能按固定30天计算。

### 4.6 `ai_user_benefit_usage`

保存当期可消耗权益：

```text
cycle_id/user_id/benefit_code
quota_total
used_amount
reserved_amount
version
```

AI任务按照 `reserve → confirm/release` 处理，失败任务必须释放预占。

### 4.7 积分表

- `ai_point_account`：可用积分、冻结积分、乐观锁版本。
- `ai_point_transaction`：不可修改的积分流水，`request_no` 唯一保证幂等。
- `ai_daily_point_reward`：`(user_id, reward_date)` 唯一，防止每日奖励重复领取。

积分和人民币钱包分开存储。积分扣减使用带余额条件的原子更新，不能先查再扣。

### 4.8 变更和退款表

- `ai_subscription_change_record`：升级、降级、续费、取消、撤销降级及金额计算。
- `ai_refund_order`：退款申请、渠道退款号、退款状态和失败原因。

## 5. 支付订单改造

`ai_payment_order` 增加：

```text
sku_id
subscription_id
order_scene
idempotency_key
refund_amount
```

订单场景：

```text
first_purchase
renewal
upgrade
point_purchase
```

支付回调：

```text
验签
→ 校验订单、渠道和金额
→ 幂等更新支付状态
→ 执行订阅或积分履约
→ 创建权益周期和使用量
→ 清理用户权益缓存
→ 标记履约成功
```

## 6. 统一权益服务

业务模块统一调用：

```java
boolean hasFeature(Integer userId, String benefitCode);
long getLimit(Integer userId, String benefitCode);
long getPointCost(Integer userId, String operationCode);
void requireFeature(Integer userId, String benefitCode);
QuotaReservation reserveQuota(Integer userId, String benefitCode, long amount, String requestNo);
void confirmQuota(String requestNo);
void releaseQuota(String requestNo);
```

购买、升级、降级生效、退款和后台修改权益后立即清除对应用户缓存。

## 7. 兼容迁移方案

1. 保留现有 `ai_membership_plan` 表名，迁移成纯套餐等级表。
2. 现有价格和周期迁移到 `ai_membership_plan_sku`。
3. 新建订阅、权益周期、使用量和积分表。
4. 现有有效 `ai_user_membership` 迁移到 `ai_user_subscription`。
5. `ai_user_membership` 暂时保留为历史兼容表，新查询切换到订阅表。
6. 现有 `ai_quota_account` 暂时保留，新会员额度统一写入 `ai_user_benefit_usage`。
7. 迁移期间不长期双写两套额度，避免出现两个真实余额。

当前工程旧实体仍有 `INT/Integer` 主键。实施时要在迁移批次中统一关联字段类型，不能长期混用 `Integer` 和 `Long`。

## 8. 验收标准

- 支付回调重复10次只履约一次。
- 同一积分或额度请求号重复提交不重复扣减。
- 年付会员按开通日准确生成月度权益周期。
- 月末开通用户在短月份不会发生周期漂移。
- 升级立即生效且已用额度不清零。
- 降级到期生效，超限历史数据不删除。
- 取消续费不会立即失去权益。
- 退款成功后权益立即失效。
- 绕过前端按钮调用接口仍会执行会员校验。
- 并发扣积分和额度不会出现负数。
