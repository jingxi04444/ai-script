## 2. 后端技术选型

建议第一阶段使用“模块化单体 + 异步任务队列”，先保证业务闭环和交付效率。

| 层 | 技术 | 说明 |
| --- | --- | --- |
| Web 框架 | Python 3.11+ + FastAPI | 适合 AI 场景、接口文档自动生成、类型清晰、开发效率高。 |
| ORM | SQLAlchemy 2.0 | 适合复杂业务模型、事务控制和后续维护。 |
| 数据迁移 | Alembic | 管理 schema 版本。 |
| 数据库 | PostgreSQL 15+ | 主业务数据、JSONB、复杂查询、多租户、事务。 |
| 向量检索 | pgvector | MVP 存结构公式、脚本特征、原创度检测向量。 |
| 缓存/队列 | Redis + RQ | 登录辅助缓存、任务进度、AI/导出异步任务；复杂后可升级 Celery。 |
| 文件存储 | S3 兼容存储，如 MinIO/OSS/COS | 图片、视频、音频、导出文件只存对象存储，数据库存元数据。 |
| 鉴权 | JWT Access Token + Refresh Token | 前台用户和后台管理员统一用户表，权限按 RBAC 控制。 |
| 权限 | RBAC + 租户上下文 | 后端强制按 `tenant_id` 隔离数据。 |
| API 文档 | OpenAPI / Swagger | FastAPI 自动生成，给前后台联调。 |
| 日志监控 | structlog + OpenTelemetry 可选 | 记录 API、任务、外部 Provider 调用链路。 |
| 测试 | pytest + factory-boy | 单元测试、接口测试、权限隔离测试。 |

为什么选 Python 后端：这个产品核心依赖大模型、文本处理、文件解析、相似度计算、视频/音频异步任务，Python 生态更顺手；FastAPI 自动生成 OpenAPI，也能降低前后端联调成本。

模块划分原则：

- `router.py` 只处理 HTTP 入参、权限依赖和响应。
- `service.py` 承载业务事务，不直接写复杂 SQL 到路由。
- `models.py` 定义 ORM 模型。
- `schemas.py` 定义 Pydantic 请求/响应。
- 外部服务统一走 `providers/`，业务模块不直接调用第三方 SDK。
- 耗时动作全部创建 `generation_tasks` 后进队列，前端通过轮询或 SSE 获取进度。

## 5. 数据库设计

已有 `doc/database/schema.sql` 已经覆盖大部分主流程。建议保留其 PostgreSQL + pgvector 方向，并在正式迁移时拆成 Alembic 迁移文件。

### 5.1 设计原则

- 主键统一 UUID。
- 所有租户数据必须带 `tenant_id`，查询层必须注入租户过滤。
- 文件不直接进数据库，数据库只存 `storage_key`、元数据、关联关系。
- 脚本版本、审核记录、支付流水、操作日志必须追加式保存。
- AI 生成、解析、导出、视频、配音全部落 `generation_tasks`，不能只依赖内存任务状态。
- 钱包金额使用 `NUMERIC(14,2)`，余额变动必须通过流水表计算和审计。
- 状态字段 MVP 可用 `VARCHAR`，后端枚举约束；稳定后再迁 PostgreSQL enum。

### 5.2 核心表分组

## 6. 关键业务流程落库

### 6.1 创建项目

1. 创建 `projects`。
2. 初始化 `project_step_states`，写入步骤：`global`、`selling_points`、`source_analysis`、`storyboard`、`visual`、`video`、`dubbing`、`preview`、`analytics`。
3. 返回项目详情给前端工作台。

### 6.2 导入卖点表格

1. 文件上传对象存储，写 `project_uploads`。
2. 后端根据 `import_template_configs` 解析列。
3. 产品型号相同则新建 `brief_versions`；不存在则创建 `product_briefs` v1。
4. 同步到 `selling_point_assets`，供资产库复用。

### 6.3 爆款链接解析

1. 前端提交链接，后端创建 `generation_tasks(task_type='parse_video')`。
2. Worker 读取 `api_provider_configs(provider_type='video_parse')`，按优先级调用。
3. 写 `parsing_logs`。
4. 保存 `source_analyses` 和 `source_analysis_reports`。
5. 可沉淀 `structure_formulas` 和 `viral_script_assets`。

### 6.4 生成脚本

1. 前端提交 `projectId`、脚本类型、模板、参考链接或 prompt。
2. 后端创建 `generation_tasks(task_type='generate_script')`。
3. Worker 读取 Brief、结构公式、Prompt 模板、合规规则，调用 LLM。
4. 创建 `storyboard_scripts`、`script_versions`、`shots`。
5. 自动触发 `compliance_checks` 和 `originality_checks`。

### 6.5 提交审核

1. 当前脚本版本生成 `audit_tasks`。
2. 按 `audit_rules` 自动分配审核员。
3. 审核动作追加写 `audit_records`。
4. 审核通过后更新 `storyboard_scripts.audit_status`。

### 6.6 视频/配音/导出

1. 每个生成动作创建 `generation_tasks`。
2. 产物上传对象存储，写 `assets`。
3. 视频片段写 `video_segments`，配音写 `dubbing_assets`。
4. 导出写 `export_jobs` 并关联导出产物 `assets`。

### 6.7 充值和会员

1. 创建 `payment_orders`，返回支付参数或二维码。
2. 支付平台回调写 `payment_callbacks`。
3. 幂等更新订单状态。
4. 充值订单写 `wallet_transactions` 并更新 `wallet_accounts.balance`。
5. 会员订单写 `user_memberships`，并按套餐写 `quota_accounts` / `quota_transactions`。

## 8. 我会采用的实现规范

- API 响应统一格式：`{ code, message, data, requestId }`。
- 列表统一分页：`page`、`pageSize`、`total`、`list`。
- 后端所有查询默认带租户过滤，超级管理员必须显式走跨租户查询。
- 外部 Provider 密钥只存加密值或 `env:VAR_NAME`，接口永不明文返回。
- 支付回调、任务回调、导出任务必须支持幂等。
- 钱包扣费使用数据库事务和行级锁。
- 删除优先软删除，审计、支付、审核、版本记录不允许物理删除。
- OpenAPI schema 作为前后台联调契约，前端类型可后续从 OpenAPI 生成。
